# AI_PROJECT_OVERVIEW — ESP32-P4 Simple Video Server

## 1. PROJECT IDENTITY
- Project name: simple_video_server
- Project type: ESP-IDF application (embedded firmware + web frontend)
- Framework: ESP-IDF (Espressif IoT Development Framework)
- Version: Based on Espressif example `simple_video_server`
- License: Apache 2.0 (Espressif examples)
- Original source: Espressif example `simple_video_server`
- Primary target chip: ESP32-P4
- All supported chips: ESP32-P4 (primary), ESP32-S3 (limited, via DVP), ESP32 (legacy DVP)

## 2. HARDWARE PLATFORM

### 2.1 Development Board: Waveshare ESP32-P4-WIFI6-DEV-KIT
- Main chip: ESP32-P4 (dual-core RISC-V up to 40MHz, with AI extensions)
- Flash: 16MB NOR flash (external, via SPI)
- PSRAM: 32MB (external, via SPI)
- Coprocessor: ESP32-C6 (WiFi6 + BLE5)
  - Connection to P4: SDIO 4-bit mode, slot 1
  - Provides WiFi6 (802.11ax) and BLE5 connectivity
  - Managed via ESP-HOSTED component (SDIO host driver)
  - WiFi control via esp_wifi_remote (RPC over EPPP link)
- Board features: MIPI-CSI camera connector, DVP camera header, RJ45 Ethernet, SD card slot, audio codec, USB

### 2.3 Camera Sensors Supported
- OV5647: MIPI-CSI, RAW8, 800x1280 @50fps (default for P4)
- SC2336: MIPI-CSI (ESP32-P4 default)
- GC2145: DVP, various formats
- OV2640: DVP, JPEG/YUV/RGB565
- GC0308: (supported but not enabled by default)

### 2.4 Camera Interfaces
- MIPI-CSI (2-lane): GPIO8/7 for I2C, dedicated HW pins for clock/data
- DVP (8-bit parallel): GPIO 2,3,4,5,6,20,21,22,23,32,33,36,37,38
- SPI: (optional)
- USB UVC: (optional)

## 4. FIRMWARE ARCHITECTURE (DEEP DIVE)

### 4.1 Source File: main/simple_video_server_example.c (907 lines)

This is the ONLY firmware source file. Everything is in here. Break it down by function.

### 4.2 Data Structures

```
web_cam_video_t: Per-camera video device
  - fd: V4L2 file descriptor to /dev/videoX
  - index: camera number (0,1)
  - encoder_handle: HW JPEG encoder (if sensor not JPEG-native)
  - jpeg_out_buf/size: Encoder output buffer
  - buffer[]: MMAP'd V4L2 frame buffers (count = CONFIG_EXAMPLE_CAMERA_VIDEO_BUFFER_NUMBER, default 2)
  - width, height, pixel_format, jpeg_quality
  - frame_rate
  - sem: Mutex for encoder access
  - support_control_jpeg_quality: flag

web_cam_t: Container
  - video_count: N cameras
  - video[]: Flexible array of web_cam_video_t
```

### 4.3 app_main() Execution Flow

```
app_main()
  ├─ nvs_flash_init()                    ← NVS storage init (auto-erase if corrupted)
  ├─ example_video_init()               ← MUST BE FIRST: provides XCLK to camera sensors
  │   └─ (from components/example_video_common)
  │       Initializes selected camera interface (MIPI-CSI/DVP/SPI)
  │       Creates V4L2 /dev/video0, /dev/video1 devices
  │       Sets up I2C (SCL=8, SDA=7) for sensor control
  ├─ esp_netif_init()                   ← TCP/IP stack
  ├─ esp_event_loop_create_default()    ← Event loop
  ├─ initialise_mdns()                  ← mDNS: esp-web.local
  │   └─ mdns_init(), mdns_hostname_set("esp-web")
  │       mdns_service_add("ESP32-WebServer", "_http", "_tcp", 80)
  ├─ netbiosns_init() / netbiosns_set_name("esp-web")
  ├─ example_connect()                  ← WiFi STA or Ethernet (menuconfig)
  │   └─ For Waveshare: ESP-HOSTED SDIO → ESP32-C6 → WiFi6
  ├─ ws_init()                          ← WebSocket client connects to CONFIG_EXAMPLE_WEBSOCKET_URL
  │   └─ Default: ws://192.168.1.100:8765
  │   └─ Sends frames: [timestamp(8B LE)|camera_id(1B)|data_len(2B BE)|jpeg_data]
  ├─ start_cam_web_server(config[], config_count)
  │   ├─ new_web_cam(config, count, &web_cam)
  │   │   └─ For each config entry:
  │   │       init_web_cam_video()
  │   │         ├─ open("/dev/videoX", O_RDWR)  ← V4L2 device
  │   │         ├─ ioctl(VIDIOC_G_FMT)           ← get format from sensor
  │   │         ├─ ioctl(VIDIOC_G_PARM)          ← get frame rate
  │   │         ├─ [optional] ioctl(VIDIOC_S_SELECTION)  ← MIPI-CSI crop
  │   │         ├─ ioctl(VIDIOC_REQBUFS)         ← request DMA buffers
  │   │         ├─ mmap() + ioctl(VIDIOC_QBUF)   ← map buffers, queue them
  │   │         ├─ set_camera_jpeg_quality()      ← via V4L2_CID or software encoder
  │   │         └─ example_encoder_init()         ← if not JPEG-native format
  │   │       ioctl(VIDIOC_STREAMON)  ← start capture
  │   └─ http_server_init(web_cam)
  │       ├─ httpd_start() on port 80
  │       │   Registers: /api/capture_image, /api/capture_binary,
  │       │              /api/get_camera_info, /api/set_camera_config,
  │       │              /* (static files: index.html.gz, *.js.gz, *.css.gz)
  │       └─ For each camera: httpd_start() on port 81,82,...
  │           Registers: /stream (MJPEG)
  └─ ESP_LOGI("Camera web server starts")
```

### 4.4 HTTP Handler Functions (Detailed)

1. **static_file_handler(req)**: Serves gzipped embedded assets
   - "/" → index.html.gz (Content-Encoding: gzip)
   - "/loading.jpg" → loading.jpg.gz
   - "/favicon.ico" → favicon.ico.gz
   - "/assets/index.js" → index.js.gz
   - "/assets/index.css" → index.css.gz
   - 404 for everything else

2. **capture_image_handler(req)**: Single JPEG snapshot
   - Parses ?source=0 from query string
   - Calls capture_video_image() with is_jpeg=true
   - Sets Content-Type: image/jpeg;name=image0.jpg

3. **capture_binary_handler(req)**: Raw binary frame
   - Parses ?source=0 from query string
   - Calls capture_video_image() with is_jpeg=false
   - Sets Content-Type: application/octet-stream

4. **capture_video_image(video, is_jpeg)**:
   - ioctl(VIDIOC_DQBUF) → dequeues frame from V4L2
   - If native JPEG format: send buffer directly
   - If non-JPEG format: run through example_encoder_process() (HW JPEG)
   - ioctl(VIDIOC_QBUF) → requeues buffer

5. **camera_info_handler(req)**: Returns JSON with all camera info
   - Calls get_cameras_json() which builds cJSON object
   - JSON shape: {"cameras":[{"index":0,"src":":81/stream","currentFrameRate":25,...}]}

6. **camera_settings_handler(req)**: POST handler for JPEG quality
   - Parses JSON: {index, image_format, jpeg_quality}
   - Calls set_camera_jpeg_quality(video, quality)
   - For JPEG-native sensors: uses V4L2_CID_JPEG_COMPRESSION_QUALITY ioctl
   - For non-JPEG: uses example_encoder_set_jpeg_quality()

7. **image_stream_handler(req)**: MJPEG stream (port 81+)
   - Infinite loop: dequeue frame → encode if needed → send via ws_send_frame()
   - Throttles to ~10fps by vTaskDelay(100ms)
   - ALSO sends frame via WebSocket to external server

8. **ws_send_frame(camera_id, jpeg_data, jpeg_len)**: WebSocket binary frame
   - Protocol: [timestamp_ms(8B LE)][camera_id(1B)][data_len(2B BE)][jpeg_data]
   - Sent to CONFIG_EXAMPLE_WEBSOCKET_URL

### 4.5 V4L2 API Usage
- All camera access is through standard Linux V4L2 API (ESP-IDF provides V4L2 compatibility layer)
- Device names: ESP_VIDEO_MIPI_CSI_DEVICE_NAME, ESP_VIDEO_DVP_DEVICE_NAME, etc.
- Operations: open, ioctl(G_FMT/S_FMT/G_PARM/REQBUFS/QUERYBUF/QBUF/DQBUF/STREAMON/STREAMOFF), mmap, close

## 5. NETWORK ARCHITECTURE

### 5.1 ESP32-P4 + ESP32-C6 WiFi Architecture
- ESP32-P4 has NO native WiFi — uses ESP32-C6 coprocessor
- Connection: SDIO 4-bit mode, slot 1
- esp_hosted component: manages SDIO host driver
- esp_wifi_remote: RPC-based WiFi control over EPPP link
- WiFi credentials: set in menuconfig (Example Connection Configuration)

### 5.2 Alternative: Ethernet
- PHY: IP101 (Waveshare board has RJ45)
- MDC: GPIO31, MDIO: GPIO52, PHY Rst: GPIO51
- Config: menuconfig → Example Connection Configuration → Ethernet

### 5.3 WebSocket Stream Architecture
- Firmware connects as WebSocket CLIENT to external PC server
- Sends binary frames: [8B timestamp][1B cam_id][2B len][JPEG data]
- This is a SECONDARY output — primary output is HTTP/MJPEG to browser

## 6. FRONTEND ARCHITECTURE

### 6.1 Tech Stack
- Vue 3.4 + TypeScript 5.6 + Vite 5.4
- Vuetify 3.6 (Material Design 3 components)
- Pinia 2.1 (state management)
- Vue Router 4.4
- @mdi/js + @mdi/font (Material Design Icons)
- Sass for styling

### 6.2 Build Pipeline
1. `pnpm i` → install dependencies
2. `pnpm compress` → vite build + gzip all output files
3. Output: frontend/gzipped/index.html.gz + assets/*.gz + loading.jpg.gz + favicon.ico.gz
4. ESP-IDF CMake: EMBED_TXTFILES embeds these .gz files into firmware binary
5. At runtime: served with Content-Encoding: gzip header

### 6.3 Component Tree
```
App.vue (v-app)
└─ router-view
   └─ index.vue (v-container max-width=600)
      └─ CameraCard.vue (v-for each camera)
         ├─ v-img: MJPEG stream from :81/stream or :82/stream
         ├─ Camera info: name, resolution, fps, quality
         ├─ Settings button → dialog with quality slider
         ├─ Camera button → download /api/capture_image?source={n}
         └─ Raw button → download /api/capture_binary?source={n}
```

### 6.4 Data Flow
1. On mount: mainStore.updateCameraStatus() → GET /api/get_camera_info
2. Response JSON: {cameras: [{index, src, currentFrameRate, currentResolution, imageFormats, currentQuality}]}
3. camera.src = ":81/stream" → constructed to URL with same hostname, different port
4. Settings save: POST /api/set_camera_config {index, image_format, jpeg_quality}
5. Polling: updateCameraStatus() calls itself every 3000ms via setInterval

### 6.5 Key Design Decisions
- v-img component displays MJPEG stream (browser-native multipart/x-mixed-replace support)
- Error handling: on image load error, waits 3s then retries
- Loading state: shows loading.jpg placeholder, then v-progress-circular
- Each camera gets its own port (81, 82, ...) for its /stream endpoint

## 9. BUILD AND FLASH

### 9.1 Prerequisites
- ESP-IDF >= 5.4 (tested with 5.4, Waveshare recommends 5.5.4)
- Node.js >= 20 (for frontend build)
- pnpm (for frontend package management)
- Python 3.x (ESP-IDF dependency)

### 9.2 Build Steps
```bash
# 1. Set target
idf.py set-target esp32p4

# 2. Configure (menuconfig)
idf.py menuconfig
# - Set WiFi SSID/Password OR Ethernet
# - Set camera sensor model
# - Set ESP-HOSTED config (for Waveshare: SDIO, C6 target)
# - Set flash size to 16MB

# 3. Build frontend (if changed)
cd frontend
pnpm i
pnpm compress
cd ..

# 4. Build + Flash + Monitor
idf.py -p COMx flash monitor
```

### 9.3 For Waveshare ESP32-P4-WIFI6-DEV-KIT
See PORTING_WAVESHARE.md — the key changes are:
1. Board: Customized Development Board (not Function-EV-Board V1.5)
2. DVP: DISABLE (to avoid pin conflicts)
3. WiFi: esp_wifi_remote with ESP32-C6 slave target
4. Flash: 16MB
5. Optionally adjust partition table for more space
